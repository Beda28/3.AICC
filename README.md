## 1. 문서 개요

AI 계산기의 제작 및 실습 과정을 정리한 문서이다.
MAC 연산을 이용해 입력 패턴을 비교하고 분류하는 과정을 확인한다.

## 2. MAC 이란?

MAC(Multiply-Accumulate)은 두 값을 곱한 뒤 그 결과를 기존 값에 계속 더해가는 연산이다.

프로그램에서는 패턴과 필터의 같은 위치에 있는 값을 곱해 합산하고, 그 점수로 패턴을 비교한다.

AI의 행렬 및 합성곱 연산에서도 MAC이 반복적으로 사용된다.

### 부동소수점 오차와 epsilon

소수 계산에는 작은 부동소수점 오차가 생길 수 있다.

따라서 두 점수를 `==`로 비교하지 않고 `abs(score_a - score_b) < 1e-9` 조건을 사용한다.

epsilon은 동점을 만드는 값이 아니라 실제 동점을 잘못 판정하지 않기 위한 허용 범위이다.

동점은 사용자 입력 모드에서 `판정 불가`, JSON 분석 모드에서 `UNDECIDED`로 처리한다.

### CPU, GPU, NPU

| 장치 | 특징 |
| --- | --- |
| CPU | 다양한 작업을 처리하는 범용 프로세서 |
| GPU | 같은 연산을 많은 데이터에 병렬로 처리하는 데 강한 프로세서 |
| NPU | 신경망의 행렬 및 MAC 연산에 특화된 프로세서 |

이 프로젝트는 NPU가 반복적으로 수행하는 MAC 연산을 간단한 형태로 구현한다.

## 3. 사용자 입력 모드

[사용된 파일](user_mode.py)

사용자가 직접 3 × 3 크기의 필터 A, 필터 B, 비교할 패턴을 입력한다.
입력된 패턴과 두 필터의 MAC 점수를 계산한 뒤 더 높은 점수를 가진 필터를 결과로 출력한다.

```bash
# 해당 결과는 실제 출력 결과입니다.
필터 A를 입력해주세요
1행 입력: 1 0 1
2행 입력: 0 1 0
3행 입력: 1 0 1

필터 B를 입력해주세요
1행 입력: 0 1 0
2행 입력: 1 1 1
3행 입력: 0 1 0

비교할 패턴을 입력해주세요
1행 입력: 0 1 0
2행 입력: 1 1 1
3행 입력: 1 1 1

A: 3 vs B: 5
판정 결과: B 필터

평균 연산 시간: 0.002810 ms
```

입력된 행의 숫자 개수가 맞지 않거나 숫자가 아닌 값이 입력되면 오류를 출력하고 해당 행을 다시 입력받는다.

## 4. data.json 분석 모드

[data.json](data.json) | [사용된 파일](json_mode.py)

패턴 이름의 `size_N_idx` 형식에서 크기 N을 추출하고, 해당 크기의 Cross와 X 필터를 선택하여 MAC 점수를 계산한다.

JSON의 `+`, `x` 등의 라벨은 프로그램 내부에서 `Cross`, `X` 형식으로 정규화하여 결과와 비교한다.

```bash
# 해당 결과는 실제 출력 결과입니다.
전체 테스트 결과
전체 케이스: 6
통과: 3
실패: 3

실패 케이스
size_5_1 / expected: X / actual: UNDECIDED
size_13_2 / expected: Cross / actual: UNDECIDED
size_25_1 / expected: X / actual: UNDECIDED

성능 분석
크기      평균 시간(ms)      연산 횟수
5x5       0.010806           50
13x13      0.047931           338
25x25      0.164342           1250
```

두 필터의 점수 차이가 `1e-9`보다 작으면 `UNDECIDED`로 판정한다.
JSON 분석 모드에서는 예상 결과를 결정하지 못한 경우이므로 FAIL로 집계한다.

## 5. 시간복잡도

### 시간복잡도란?

시간복잡도는 입력 크기에 따라 연산량이 증가하는 정도를 나타낸다.
N × N 패턴을 필터 하나와 비교하면 N²번, Cross와 X 두 필터와 비교하면 `2N²`번 연산한다.
Big-O에서는 상수를 제외하므로 시간복잡도는 `O(N²)`이다.

| 크기      | MAC 연산 횟수 |
| ------- | --------: |
| 5 × 5   |       50회 |
| 13 × 13 |      338회 |
| 25 × 25 |    1,250회 |

### 실행 시간 측정

JSON 파일 읽기와 출력은 제외하고, 각 테스트 케이스에서 Cross와 X의 MAC 연산 구간만 10회 측정하였다.

| 케이스       | 결과   |      10회 평균 |
| --------- | ---- | ----------: |
| size_5_1  | FAIL | 0.005750 ms |
| size_5_2  | PASS | 0.004600 ms |
| size_13_1 | PASS | 0.023020 ms |
| size_13_2 | FAIL | 0.023070 ms |
| size_25_1 | FAIL | 0.113290 ms |
| size_25_2 | PASS | 0.090210 ms |

크기별 성능은 각 크기의 유효한 패턴 하나를 사용하여 MAC 연산 구간을 별도로 10회 측정하였다.

| 크기      | 평균 시간(ms) | MAC 연산 횟수 |
| ------- | --------: | --------: |
| 5 × 5   |  0.005175 |        50 |
| 13 × 13 |  0.023045 |       338 |
| 25 × 25 |  0.101750 |     1,250 |

### 결과 해석

패턴 크기가 증가할수록 처리할 원소 수와 평균 실행 시간이 증가하는 경향을 확인했다.
실행 시간은 환경에 따라 달라지지만, 코드가 N × N의 모든 원소를 순회하므로 시간복잡도는 `O(N²)`이다.

## 6. 2D와 1D 연산 비교

[사용된 파일](bench.py)

같은 Cross 필터, X 필터, 랜덤 패턴을 현재 2D 방식과 1D 직렬 방식으로 계산하였다.
각 계산 구간을 10회 실행하여 평균을 구했으며, 1D 방식은 변환 시간도 별도로 측정하였다.
실행 시간은 사용 환경과 실행 시점에 따라 달라질 수 있다.

| 방식 | 계산 방법 |
| --- | --- |
| 현재 2D | 2차원 필터와 패턴을 중첩 반복문으로 계산 |
| 1D 직렬 | 2차원 데이터를 1차원으로 변환한 뒤 하나의 반복문으로 계산 |

| 크기 | 2D 계산(ms) | 1D 계산(ms) | 변환(ms) | 변환 포함 1D 전체(ms) |
| --- | ---: | ---: | ---: | ---: |
| 25 × 25 | 0.065 | 0.054 | 0.059 | 0.113 |
| 100 × 100 | 0.979 | 0.865 | 0.521 | 1.386 |
| 1000 × 1000 | 112.864 | 87.846 | 77.917 | 165.763 |
| 2000 × 2000 | 435.494 | 376.619 | 297.262 | 673.881 |

### 결과 해석

순수 계산 시간은 모든 크기에서 1D 직렬 방식이 현재 2D 방식보다 짧게 측정되었다.
1D 방식은 중첩 리스트에 접근하지 않고 연속된 배열을 하나의 반복문으로 순회한다.

그러나 2D 배열을 처음 1D로 변환하는 시간을 포함하면 모든 크기에서 현재 2D 방식이 더 빨랐다.
따라서 한 번만 계산할 때는 2D 배열을 그대로 사용하는 것이 효율적이다.
같은 데이터를 반복 계산한다면 최초 변환 비용이 분산되므로 1D 방식이 유리해질 수 있다.

모든 크기에서 2D와 1D의 MAC 점수가 일치하여 두 구현이 같은 계산 결과를 내는 것도 확인하였다.
두 방식 모두 N²개의 원소를 확인하므로 시간복잡도는 `O(N²)`이다.

## 7. 결과 리포트(실패 원인 + 복잡도)

### 분석 결과

`data.json`에 저장된 6개 패턴을 Cross와 X 필터로 분석하였다.

전체 결과는 통과 3개, 실패 3개로 확인되었다.

실패한 케이스는 `size_5_1`, `size_13_2`, `size_25_1`이며, 세 케이스 모두 예상 결과는 Cross 또는 X였지만 실제 결과는 `UNDECIDED`였다.

### 실패 원인

실패한 세 케이스에서는 필터 가중치와 입력 패턴의 조합으로 Cross와 X의 MAC 점수가 같거나 매우 가까운 값이 계산되었다.

epsilon이 동점을 만든 것이 아니라, 이미 두 MAC 점수가 같거나 매우 가까운 상태에서 부동소수점 오차를 고려하여 동점 여부를 판단한 것이다.

프로그램은 다음 조건을 사용한다.

```text
abs(score_a - score_b) < 1e-9
```

조건을 만족하면 두 점수를 동점으로 판단하고 JSON 분석 모드에서는 `UNDECIDED`를 반환한다.

`UNDECIDED`는 `data.json`에 저장된 예상 결과인 Cross 또는 X와 일치하지 않기 때문에 FAIL로 집계되었다.

### 성능 결과 해석

시간복잡도 분석을 통해 MAC 연산은 패턴의 크기가 증가할수록 필요한 연산량이 제곱 단위로 증가하는 `O(N²)` 구조임을 확인하였다.

5 × 5, 13 × 13, 25 × 25의 기본 실험에서도 패턴 크기가 증가하면서 평균 실행 시간이 증가하는 경향을 보였다.

실행 시간은 시스템 상태와 Python 실행 환경에 따라 달라질 수 있으므로 연산 횟수와 정확히 같은 비율로 증가하지는 않는다.

추가 실험에서는 같은 MAC 연산을 현재 2D 방식과 1D 직렬 방식으로 비교했으며 두 방식의 계산 결과는 모두 일치하였다.

순수 계산 구간에서는 1D 방식이 더 빨랐지만, 최초 변환 시간을 포함한 한 번의 전체 실행은 2D 방식이 더 빨랐다.

따라서 한 번 계산할 때는 기존 2D 방식이 적합하고, 같은 데이터를 반복 계산할 때는 변환된 1D 데이터를 재사용하는 방식이 유리할 수 있다.

배열 구조가 달라도 두 방식 모두 N²개의 원소를 순회하므로 시간복잡도는 `O(N²)`으로 동일하다.
